## Context

PRD §4.7 是整个分发引擎的基石：

> 内容侧 `content.labels` = `[{label_id, confidence, source}]`，按层展开为 12 维稀疏向量；
> 用户侧 `user_profile.tag_weights` = `{label_id: weight}`，同一 `label_id` 空间；
> 交互：内积 `Σ w_content[label] × w_user[label]` = 标签偏好匹配分。

PRD §10-Q9 指出这一节未定义的部分：

> 「L1-L12 各层如何加权合成一个标签向量」尚无定义：是否按层赋权（树层权重递减）？是否用 IDF 抑制高频标签？
> 建议：**按层赋权（L1-L4 权重高，L5-L12 低）+ IDF 归一化**，权重在配置中可调并写入 `pipeline_version`，保证口径可复现；用 `content_vector.tag_vector` 与 `user_profile.tag_weights` 存同一空间。

主理人决策 Q9 已确认：**按层赋权（L1–L4 高，L5–L12 低）+ IDF 归一化，权重写进配置并记入 `pipeline_version`；`content_vector.tag_vector` 与 `user_profile.tag_weights` 同一空间；层权重需给出默认值与可配置项。**

需要本 ADR 确定的是**具体公式、默认层权、IDF 变体、以及「同一空间」的工程保证机制**。

关键子问题：

1. **层权怎么定？** 12 个层各自的重要性显然不同，但具体数值是主观的。需要一套有理由、可辩护、可调的值。
2. **IDF 用哪种变体？** 平滑方式、是否取对数底数、是否有上限。
3. **置信度怎么进入向量？** `labels[].confidence` 是 0–1 的软置信度，直接作为系数会让低置信标签几乎不产生区分度。
4. **「同一空间」如何在工程上保证？** 两张表、两次写入、可能不同批次的重建 —— 口径漂移是真实风险。
5. **稀疏向量在 10 万行上如何支撑 P99 ≤ 100 ms？**

## Decision

### 决策 1 · 层权默认值与配置化

**层权表**（写在 `config/thresholds.py`，计入 `tag_space_version`）：

| 层 | 层名 | 默认权重 | 理由 |
| --- | --- | --- | --- |
| L1 | 领域域 | **1.00** | 顶层归属，最强区分信号；PRD §4.1「是（强特征）」 |
| L2 | 一级类目 | **1.00** | 主业务类目，强特征 |
| L3 | 二级类目 | **0.80** | 细分方向，仍是强特征但弱于 L1/L2 |
| L4 | 主题簇 | **0.80** | 具体议题，强特征 |
| L5 | 事件与场景 | **0.55** | 开放多选层，弱于树形层 |
| L6 | 人物实体 | **0.55** | PRD §4.1「是（弱特征）」 |
| L7 | 机构与品牌 | **0.55** | 弱特征 |
| L8 | 地理与场所 | **0.55** | 弱特征 |
| L9 | 商品与作品 | **0.55** | 弱特征 |
| L10 | 属性与量化 | **0.30** | PRD §4.1「否（进画像但不入向量）」→ 最低权 |
| L11 | 消费意图 | **0.75** | PRD §4.1「是（强特征）」，虽在开放层但语义强度高 |
| L12 | 情感·立场·风险 | **0.75** | PRD §4.1「是（强特征）」，含互斥组 |

**设计原则**：

- **树形层（L1–L4）权重 > 开放层（L5–L9）**，体现「层级越浅语义越强」与 PRD §4.1 的「前紧后松」设计。
- **L10 最低**：PRD 明文规定它「不入召回特征」，既然要进向量，就给最低权（0.30），使其在归一化后影响可忽略。
- **L11/L12 例外**：它们在开放多选层中，但 PRD 标为「强特征」，且 L12 的互斥组机制（正面/负面/中立）语义信息量极高，因此给 0.75。

**配置形式**：

```
TAGMIND_TAG_LAYER_WEIGHTS = {
  "1": 1.00, "2": 1.00, "3": 0.80, "4": 0.80,
  "5": 0.55, "6": 0.55, "7": 0.55, "8": 0.55, "9": 0.55,
  "10": 0.30, "11": 0.75, "12": 0.75,
}
```

变更层权 → `tag_space_version` 变化 → 触发全量 `tag_vector` 重建 → **必须走灰度**（否则线上召回分数漂移不可解释）。

### 决策 2 · IDF 变体

$$
idf(\ell) = \ln\left(\frac{N+1}{df(\ell)+1}\right) + 1
$$

- **平滑项 `+1`**：`df=0`（新标签）时 IDF = $\ln(N+1)+1$，取最大值；`df=N`（所有内容都有）时 IDF = 1（最小值）。两者都不为 0 或负，避免除零与负权重。
- **`+1` 尾部常数**：保证 IDF ≥ 1，与层权相乘后不会把一个标签压成 0。
- **自然对数**：与余弦相似度无冲突（对数底数只影响相对比例的缩放，不影响排序，但用 $\ln$ 与 ML 惯例一致）。
- **`df` 物化到 `label_def.df_count`**：由 `scheduler/tasks/maintenance.py` 每日刷新（全量扫描 10 万行 < 5 s），`idf` 作为派生列一并缓存。召回路径上不做全局统计。
- **`TAGMIND_TAG_IDF_ENABLED`** 开关：允许在 A/B 中关闭 IDF，验证其实际贡献。

**IDF 的实际作用**：抑制「财经 / 生活」这类高频泛标签的支配作用。在 10 万条语料下，若「生活消费」的 df = 30000 而「AI 芯片」的 df = 200，则 IDF 分别为 2.2 与 8.5 —— 相差近 4 倍。没有 IDF，「生活消费」会在任何内容的向量里都占据巨大分量，使路 A 退化为「是不是生活类内容」的二值判断。

### 决策 3 · 标签向量公式

$$
v(c)[\ell] = w_{layer(\ell)} \cdot idf(\ell) \cdot p(c,\ell)
$$

其中 $p(c,\ell) \in [0,1]$ 是标签置信度。**置信度直接作为线性系数**（不做幂变换），理由：

- 置信度本身已经是模型给出的 0–1 后验概率，线性加权是最直接的解释；
- 幂变换 $p^\gamma$（$\gamma>1$）会过度压制 0.6–0.8 区间的标签，而这些标签恰恰是「大概率对但不确定」的多数派，过度压制会让路 A 召回过窄。
- 线性系数的可解释性最好：可以说「这条内容的『人工智能』标签贡献了 0.92 的权重」。

**归一化**：L2 归一化，$\hat{v}(c) = v(c)/\|v(c)\|_2$。

- `content_vector.tag_vector` 存**未归一化**的 $v(c)$（JSONB `{label_id: value}`），`tag_vector_norm` 存 $\|v(c)\|_2$。
- 归一化在读取时计算：便于调参后重算，无需重写存量。

**`source='derived'` 的处理**：自动补齐的祖先标签**不参与**向量计算。否则 L1 权重 1.00 会被强制加到每条内容上，L1 维度失去区分度（所有内容的 L1 分量都很大且近似相等）。

### 决策 4 · 「同一空间」的工程保证

这是 Q9 最容易被忽略的部分。两侧要真正「同空间」，必须同时满足：

| 保证项 | 实现 | 校验 |
| --- | --- | --- |
| 标签 ID 空间一致 | 两侧 key 都是 `label_def.id`（BIGINT），不是 code 也不是 name | `scripts/consistency_check.py` V2 |
| 权重口径一致 | 两侧都由 `vector/tag_space.py` 的同一函数计算层权与 IDF | 单测断言两侧调用同一实现 |
| 版本绑定 | 两侧都存 `tag_space_version` | V5：版本不一致数必须为 0 |
| 归一化一致 | 两侧都用 L2 归一化 | V3 / V6 |
| 增量同步 | 体系发布新版本 → 调度触发全量 `tag_vector` 重建 | 重建完成后 V5 归零 |

**版本不一致时的行为**：**拒绝打分**并降级为召回 A（只用标签偏好），同时告警。绝不「用新标签体系算内容向量、配旧权重算用户画像」—— 那样得到的相似度是**无意义的数字**，比不给分数更危险。

### 决策 5 · 稀疏存储与高性能检索

**真相源 vs 索引分离**：

| 层 | 载体 | 用途 |
| --- | --- | --- |
| 真相源 | `content_vector.tag_vector`（JSONB）+ `tag_vector_norm` | 持久化、可重建、权威 |
| 倒排索引 | `content.label_ids BIGINT[]` + GIN | 快速筛出「命中用户 Top 标签」的内容候选集 |
| 在线索引 | 进程内 **CSR 稀疏矩阵**（`float32`） | 精确内积打分 |

**两段式召回**（路 A）：

```
段 1：candidate_ids = SELECT id FROM content
                     WHERE label_ids && top30_user_label_ids
                       AND status='approved' AND quality_status='approved'
                     LIMIT 2000
段 2：在 CSR 矩阵上对候选做精确余弦 → top 200
```

- 段 2 复杂度：CSR 矩阵 10 万行 × 平均 20 非零/行，`float32` 约 8 MB，单用户一次点积 < 0.2 ms。
- 段 1 用 GIN 索引，`LIMIT 2000` 后段 2 的计算量微不足道。
- CSR 矩阵由 `vector/indexer.py` 周期刷新（每 30 s 从 Redis `/2` 拉快照），写路径通过 pub/sub 立即失效重建（见 ADR-0006）。

## Consequences

### 正面

- **路 A 有明确的数学定义**，可解释、可复现、可调。回答「为什么推这个」时，能直接说「你的『人工智能』权重 0.31 × 内容的『人工智能』置信度 0.92」。
- **层权 + IDF 的组合解决了两个真实问题**：层权处理「不同层的语义强度差异」，IDF 处理「同层内的高频泛标签」。两者都在配置里，可被 A/B 验证。
- **10 万规模下 P99 ≤ 100 ms 可达**（§8.4 预算：段 1 8 ms + 段 2 4 ms）。
- **口径可追溯**：层权与 IDF 的任何变更都记入 `tag_space_version`，并被 `pipeline_version` 引用 → 满足 §7.5 声明 6（指标绑定版本）。
- **「同一空间」有了机器校验**（V2/V3/V5/V6），不靠人工承诺。

### 负面 / 代价

- **层权是主观的**。默认值有理由但无实证。缓解：全部可配 + 可 A/B + `tag_space_version` 记录。
- **IDF 需要周期性全量统计**。10 万行每日 5 s，可接受；100 万行后需要增量统计或预计算（PRD §8.5.1 的扩容路径）。
- **JSONB 存储不是查询友好格式**。这是 ADR-0001「pgvector 为真相源 + 进程内 CSR 为索引」折中的代价；换来的是「可从 content 表重建」（NF-R09）。
- **`source='derived'` 被排除在向量外**，这意味着祖先补齐不提升内容的语义表示 —— 这是有意的（否则 L1 失去区分度），但需要在文档中说明，否则容易被误认为 bug。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 层权调错导致召回质量下降 | 配置化 + `tag_space_version` + 灰度重建 + 离线回放对比（`evaluation/replay.py` 的纯标签基线正是为此设计） |
| `df_count` 陈旧 | 每日刷新 + 一致性校验比对 `df_count` 与实际值（误差 > 5% 告警） |
| CSR 快照与 DB 不一致 | pub/sub 失效 + 30 s TTL + V2/V3 校验 |
| 标签体系升级后用户画像未重建 | V5 版本检查发现不一致 → 自动触发画像重建 + 告警 |
| 有人绕过 `tag_space.py` 直接算权重 | 该模块是**唯一**实现层权与 IDF 的地方，其他模块只能调用它；`mypy` 与 code review 保证 |

## Alternatives Considered

| 方案 | 为何被否 |
| --- | --- |
| **不做层权（所有标签权重相同）** | ① L1 与 L10 的语义强度差异被抹平，路 A 退化为「标签数量多就相似」；② 与 PRD §4.1 的「前紧后松、强/弱特征」设计直接矛盾；③ 无法通过配置调优。 |
| **层权用固定递减公式（如 $w_k = 1/k$ 或 $2^{-k}$）** | ① L11/L12 是强特征但会拿到极小权重，与 PRD §4.1 矛盾；② L10 需要的是「几乎不参与」而非「按公式衰减」；③ 无法针对业务调整。**改为查表 + 明确的业务理由。** |
| **只做 IDF，不做层权** | 同上第一点。且 IDF 无法表达「层」的语义差异（df 相近的 L2 与 L10 标签会得到相近权重）。 |
| **只做层权，不做 IDF** | 高频泛标签支配向量，路 A 退化为二值判断。这是 Q9 明确要求 IDF 的原因。 |
| **IDF 用 $\ln(N/df)$ 不做平滑** | `df=N` 时 IDF=0 → 乘积为 0 → 该标签对所有内容无区分度（恰好「生活消费」这类标签会变成 0，反而丢信息）；`df=0` 时除零。必须平滑。 |
| **IDF 用 BM25 的变体** | BM25 需要文档长度归一化与词频饱和，作用在「标签」而非「词」上，语义不匹配；且需要额外的超参（k1、b），增加调参面。 |
| **置信度做幂变换 $p^\gamma$** | 过度压制 0.6–0.8 区间的标签，让路 A 召回过窄；线性可解释性更好。 |
| **把 `content.labels` 直接展平成 12 维稠密向量（每层一个数）** | ① 一个内容在一层有多个标签时无法用一个数表示；② 丢失标签身份，路 A 无法与用户的 `tag_weights`（按 label_id）内积；③ 与 PRD §4.7 的「同一 label_id 空间」直接冲突。 |
| **用稠密向量（1024 维）代替标签向量做路 A** | ① 不可解释，无法回答「为什么推这个」；② 无法做同 L2 打散；③ 冷启动内容没有向量时完全无法参与路 A。 |
| **把标签向量直接存成 PostgreSQL 的 `float4[]` 或 `sparsevec`** | `sparsevec` 是 pgvector 0.7+ 的新类型，与 JSONB 相比可查询但失去了「按 label_id 灵活增减」的便利，且需要额外的维度定义（须固定 1800 维）→ 标签体系扩容时要做全表 ALTER。JSONB + 进程内 CSR 更灵活。 |
